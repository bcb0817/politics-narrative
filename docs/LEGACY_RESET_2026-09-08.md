# 旧モデル生成物の整理（2026-09-08）

ユーザー指示により、2026-09-08 00:00 JSTより前の運用生成物を整理した。
Bot・関連投稿タスクは停止したまま。外部投稿・API呼び出しは行わない。

## 除去範囲

- 運用領域の旧ファイル2,891件を復旧用バックアップへ退避し、元の場所から除去。
- 現行ログ5本の過去分46,727行を削除。今日の行と日付を確定できない行は保持。
- 候補在庫316件、未公開実験割当5件、旧学習結果1件、日次/週次レビュー10件をDBから除去。
- 未公開旧生成投稿401件の本文・Threads本文を消去し、`retired_legacy` に変更。
- 旧note草稿15件、反応候補1件、視覚/スレッド/動画/長文候補12件、返信/引用候補10件、
  不採用social_anger候補122件を使用停止し、主要生成本文または参照パスを消去。
- 監査用ID・一部補助メタデータは残す。安全性不明の状態を公開済みや未送信に変更しない。

対象はallowlist内のログ、キャッシュ、outputs、reports、未追跡の旧学習パターン等。
更新日時が今日の非ログファイルは対象外。今日のAstra実装・検証ファイルも対象外。
依存関係のあるソース、設定、テスト、既存の未コミット開発は日付だけで削除しない。

## 残す記録と旧版の影響遮断

公開済み投稿、メトリクス、重複防止履歴、X/Threads送信状態、費用台帳・予約、
認証情報・.envは保持。削除すると二重投稿や費用再使用につながるため。
新しい選定では過去の全投稿を重複防止にだけ使い、テーマ・形式の成績や偏りの評価には
同じAstra生成バージョンの履歴だけを使用する。
実験の形式履歴・割当数も生成バージョンで分離し、旧版の未公開割当は再利用しない。
公開済み旧割当は監査用に保存する。旧学習モデルの自動流用は引き続き無効。

## 実行と復旧

バックアップは `production/create_backup.ps1 -Label legacy-cleanup` で先に作成。
保存先: `backups/politics-narrative-backup-legacy-cleanup-20260908-144754`。
運用除去ファイルとログ原本は同バックアップ内の `retired-runtime/`、一覧は
`cleanup-manifest.json`。DB原本は `data/bot_metrics.db`。
バックアップはBotの読取対象外で、GitHubには公開しない。物理的な完全消去ではなく復旧可能な運用削除。

再実行はまずdry-runで確認する。

```powershell
production/clear_legacy_runtime.ps1 -Quarantine '<作成済みバックアップ絶対パス>'
.venv/Scripts/python.exe production/clear_legacy_state.py --backup '<作成済みバックアップ絶対パス>'
```

適用はそれぞれ `-Apply` / `--apply`。日時既定値はこの整理日のJST境界であり、日次清掃タスクではない。
PowerShellはリポジトリ外・reparse point・追跡ファイルを拒否する。
DBは単一トランザクション、送信不明payloadのハッシュ一致は保持、日付不明は削除しない。
バックアップ済み原本を戻す場合もBotを停止し、今日の状態を上書きせず必要な対象だけ照合して復元する。

検証: 日時境界、dry-run、再実行、公開/ambiguous/費用台帳の保持、旧履歴と新選定の分離を回帰テスト。
SQLite `integrity_check=ok`。この整理はインプレッション向上の実証ではない。
