# 通常Xニュース解説：日次10件の自動運用

## 変更理由と範囲

2026-10-05、ユーザーが「通常の短文X投稿10件/日」を指定。
それ以前は14タスクDisabled、RSSと記事生成は手動のみ、公開は1回の固定テスト専用でした。
投稿されなかった主因は自動公開経路が無かったことです。長文生成も2実行とも未完成でした。
今回、既存のRSS取得・資料取得・xAIクライアント・予算台帳・X OAuth接続を再利用し、
`local_bot.py short`へ接続しました。長文記事のauto_publishはfalseのままです。

## 起動・停止

```powershell
Set-Location 'D:\SNS Bot\politics-narrative'
python -X utf8 local_bot.py short status   # ローカル集計だけ
python -X utf8 local_bot.py short dry-run  # API/公開なし、設定確認
python -X utf8 local_bot.py short prepare  # 有料生成・独立検証のみ。公開なし
python -X utf8 local_bot.py short run      # 本番と同じ。条件合格時に最大1件公開
```

`production/install_short_task.ps1 -Enable`は既存PoliticsNarrativeBotだけを20分間隔へ変更します。
`production/run_short_posts.ps1`が絶対パスのPythonを用いて実行します。
未指定時のinstallはDisabledとして登録。旧タスクがRunningなら変更せず停止します。
元のタスクXMLは作業前のリポジトリ内バックアップに保存。
Threads/動画/災害/旧レビュー等13タスクは変更しません。

停止は`Disable-ScheduledTask -TaskName PoliticsNarrativeBot`。
実行中も止める場合は`Stop-ScheduledTask -TaskName PoliticsNarrativeBot`。
さらに`config/short_posts.json`のenabledをfalseにします。送信中に強制停止した場合は
sendingが残り、再起動しても再送せず照合待ちになります。DBを削除して再実行しないでください。
Windowsの既存ユーザープリンシパル（Interactive）を維持します。ログオン・PC稼働が必要です。
WakeToRun/StartWhenAvailableを設定しますが、電源断やログオフ中の稼働は保証しません。

## 投稿時刻と件数

JST 08:00、09:30、11:00、12:30、14:00、15:30、17:00、18:30、20:00、21:30を目標枠とします。
20分間隔のタスクで到来済み枠と当日成功数を比較し、不足なら最大1件だけ投稿。
最短間隔60分、23時以降は公開しません。欠けた枠は後続実行で補いますが、連投で穴埋めしません。
日次成功10件で停止し、既存.envのX日次/月次上限も超えません。遅い時刻の開始日は未達の可能性があります。
1実行最大2候補、1日最大20候補の生成試行。枠を埋めるための品質・安全性の緩和はありません。
形式・転載・文字数の問題は、未公開の同じ候補について予算内で最大1回だけ修正し、再度独立検証します。
実質的根拠不足を修正対象として無理に通したり、公開済みニュースを再送したりしません。

## 編集と検証

初期対象はNHK政治RSS。RSSの要約ではなく、実際に取得できるニュース本文の範囲で作成。
一次資料未確認の報道は「NHKによると、」と帰属させ、独立確認済み事実のようにしません。
ニュースの意味・条件・段階を短く説明し、未取得の背景、効果、意見、告発を足しません。
従来の長文記事に対する一次資料要件や人間レビュー要件は変更していません。

xAI生成と別の検証呼び出しで全主要主張・条件・帰属を照合。
原文引用をモデルに書き直させず、取得本文の段落番号からプログラムで正確に保存します。
検証で根拠段落が存在しない、全主張が網羅されない、未承認などの場合はneeds_researchで除外。
45文字を超える連続転載、類似本文、同一URL/見出しの再利用、期限切れを拒否。
取得可能な本文の範囲を超える断定は不可。モデル検証は誤りを完全に除去する保証ではありません。
日本語等を2として保守的に280以内の重み付き文字数を検査し、切り詰めで条件を落としません。
初期版はURLなしの本文で、出典URL・根拠・検証は内部保存。公開URL挿入の課金は利用しません。

## 公開・費用の安全性

- 既存POST_ENABLED/X_POST_ENABLEDがtrueでなければ送信しません。.envは変更しません。
- 1日1回かつ認証情報変更時にGET /2/users/meで指定アカウントのID/ユーザー名を確認。
- 送信前にSQLiteへ費用予約とsending状態を確定。POSTは自動再試行しません。
- 応答不明・途中停止は全公開を保留。401/402/403やアカウント不一致も停止し、原因確認が必要。
- 同じ共有実行ロックを記事生成と利用。タスクも多重実行IgnoreNew。
- 既存の総額・xAI・X月次予算と予備費を共通台帳で維持。短文生成の1候補上限は$0.25。
- xAIの実費欠測・応答不明は予約を保持。課金上限をAPI側で厳密保証するものではありません。
- Xは通常投稿$0.015、User Read $0.010を予約。実費は別途請求確認が必要。
  2026-10-05確認：https://docs.x.com/x-api/getting-started/pricing
- 単純に月31日10件ならX投稿$4.65＋日次確認$0.31の見積り。xAI費用は生成と検証の実使用量次第。
- 他アプリや削除済み台帳、手動投稿を含むアカウント全体の使用量を完全には把握しません。

## 記録・未達の確認

`data/short_posts/latest.json`に本日/前日の成功件数・不足件数・除外理由・直近投稿URLを保存。
対象は今回の短文経路のみで、開始前のアカウント全投稿を復元した統計ではありません。
`data/bot_metrics.db`のshort_items/short_x_calls/short_events/short_stateと既存article_callsが証跡。
`outputs/short_posts/<source-hash>/`に取得資料・本文案・検証・根拠・使用量を保存。
全部Git対象外です。秘密情報は保存しません。

`halt`またはsending/ambiguousがあれば、Xの当該アカウントで本文・投稿IDを照合してから人間が復旧判断します。
この初期版には結果不明を自動解放する機能はありません。未達を理由に停止条件を迂回しません。
定期タスクが停止している場合はGet-ScheduledTaskInfoのLastTaskResultとNextRunTimeも確認してください。
