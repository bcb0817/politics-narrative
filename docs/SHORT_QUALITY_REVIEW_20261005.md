# 投稿品質監査と未公開比較 — 2026-10-05 JST

## 対象と観測

本番DBのshort_itemsから直近最大100件を照会し、取得できた公開ニュース投稿は6件（2026-10-05 11:29〜17:52 JST）。
過去100件が存在したとは扱わない。固定テスト投稿・バックアップ内の廃止済み履歴は今回のニュース母集団に含めない。

- 同じ「NHKによると、」の書き出し：6/6件。
- 【論評】ラベル：5/6件。
- 1段落：6/6件。文字数は85、130、122、121、121、123字。5/6件が121〜130字。
- 注意例として挙がった「今後の動向に注目」「本質は」「皆さんはどう思いますか」等の監査対象10表現は、保存済み6件ではいずれも0件。存在しない反復を問題として数えない。
- 完全に同じ結び12文字は0組。一方、複数の論評が「負担・数字・説明責任という評価基準の宣言」にとどまる点は編集上の観察であり、自動的に測定した意味的重複率ではない。
- 「国会開会式」の保存済み取得資料には関連記事の見出しが混入し、投稿も関連報道の減税話題を持ち込んでいた。本文抽出範囲を修正した。
- インプレッション、読者評価、プラットフォームの自動化判定との因果は未測定・未確認。

コード上の直接原因は、固定冒頭・ラベル・意見・120〜130字を要求していたこと、過去投稿を生成/審査に渡していなかったこと、
全文の文字列類似度だけで落としていたこと、本文以外も根拠段落として与えていたこと。

## 実装

config/short_editorial.mdとconfig/short_posts.jsonで1投稿1論点、可変長、速報/見送り、比較40件、修正最大1回を設定。
src/short_quality.pyに事実整理/論点/文型スキーマ、公開抜粋抽出、5軸の独立審査、数字・引用・代表的な段階表現のガードを追加。
src/short_posts.pyの本番経路で使用し、short_editorialテーブルと出力ファイルへ保存。旧版待機稿は対象外。
同URLの内容版IDと新事実検証により続報候補を扱い、過去投稿と元の有効期限を保持する。
production/review_short_quality.pyは同じ生成処理を使う非公開比較CLI。検証DBはoutputs内、費用だけ既存台帳へ合算する。
tests/test_short_posts.pyとtests/test_short_quality.pyに回帰ケース。運用/切戻しはdocs/SHORT_POSTS.md。

## 比較の読み方

実際にHTTP取得できたNHKニュース10件の公開抜粋を使用。ログインやアクセス制限は迂回していない。
8件にAfter候補を生成し、2件は素材不足で生成段階から見送り。下記の不合格案は完成品ではなく検証結果として掲載する。
Beforeの6件は保存済み公開投稿、残る4件は旧来の定型を説明する再構成（旧モデルを再実行した出力ではない）。
同URLでも記事が更新されている場合があり、BeforeとAfterが同一時点・同一入力のA/B比較とは限らない。
公開済みBefore自体には今回新しい投稿操作を行っていない。Afterはすべて未公開。
同URLの旧稿は書き換え評価だけのため履歴から除外。本番では除外しないので、これら5件をそのまま再投稿できる意味ではない。

独立モデル審査の○は読者の評価や人間による事実確定ではない。プログラムの根拠/文字数/主張対応検査も別に適用する。
最初の審査で抽象的な論評が通ったため、評価軸の宣言だけの文章を除外する基準を具体化し、生成済み候補に最終審査を実施。
1件は文体不合格を最大1回だけ修正。最終結果：5件合格、5件見送り。合格例にも事実速報が多く、鋭い論評が安定生成できると実証したわけではない。
