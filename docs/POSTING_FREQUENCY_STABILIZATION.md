# 投稿機会の安定化 📈

## 目的

ニュースの検証、重複禁止、安全性、BANリスク、投稿間隔、日次上限、
月間予算を緩和せず、OpenAI候補生成の空振りを減らします。

## 診断根拠 🤖

2026-07-31に、投稿本文・アカウント情報・認証情報を除いた直近の集計を
ChatGPTへ渡して運用診断を行いました。

- 直近7日の日別成功数は `1, 0, 2, 3, 7, 4, 3` で、日ごとの変動が大きい状態でした。
- ログでは `politics_api_call_limit` が17回、
  `candidate_generation_failed` が12回記録されていました。
- ChatGPTは、品質基準を下げるのではなく、多段生成のAPI浪費削減、
  短時間キャッシュ、段階的フォールバック、失敗経路の可視化を優先するよう提案しました。
- 採用したのは、既存の安全策と予算上限を変更しない対策だけです。

## 実装

- `POLITICS_LEGACY_FALLBACK_RESERVE_CALLS=1`
  - 多段生成が失敗した場合に備え、軽量生成1回分を予約します。
  - 残りのAPI枠で次の多段再試行を完了できない場合は、早めに軽量生成へ切り替えます。
- `POLITICS_CANDIDATE_CACHE_ENABLED=true`
  - 生成できた未投稿候補を短時間だけ保存し、次の監視枠で再利用します。
- `POLITICS_CANDIDATE_CACHE_TTL_HOURS=4`
  - 候補キャッシュの有効期間です。
  - URL、見出し、公開日時、要約、プロンプト版のいずれかが変わると再利用しません。
- 候補生成に失敗した場合、API呼び出し数、対象記事数、キャッシュ設定を
  投稿試行ログへ記録します。

## 維持する安全策 🔒

キャッシュ候補にも、投稿直前に次の既存判定を適用します。

- 一次情報・信頼できる情報源の確認
- 同一政策で進展がない場合の72時間重複禁止
- topic cooldown
- 45分の最短投稿間隔
- 品質スコア
- BANリスク
- 日次投稿上限
- OpenAI・X・合計API予算

最低投稿数をノルマ化したり、安全基準を下げたりはしません。

## 日次20件の目標 🎯

`ORIGINAL_DAILY_POST_MIN=20`を運用目標、`ORIGINAL_DAILY_POST_MAX=20`と
`MAX_DAILY_AUTOMATED_POSTS=20`をハード上限とします。速報はこの20件の内数で、
別枠で総数を超えません。X APIの作成枠も日次20件・月次600件に揃えます。
05:00〜23:00の45分間隔（約25監視枠）で、品質条件を満たす候補だけを投稿します。
未達時は候補不足、品質、安全、重複、冷却時間、予算、API失敗を分析しますが、
未達を埋めるための強制投稿や品質・安全基準の引き下げは行いません。

本番`.env`への反映はバックアップ後、プレビューを確認して明示適用します。

```powershell
& ".\production\create_backup.ps1" -Label "before-daily-target-20"
& ".\production\set_daily_post_target.ps1"
& ".\production\set_daily_post_target.ps1" -Apply
```

最後のコマンドは`.env`の対象キーだけを更新し、秘密値を表示しません。
設定読込がモジュール初期化時に行われるため、反映にはBotの手動再起動が必要です。
スクリプト自身はBot再起動やWindowsタスク変更を行いません。
