# social_radar — 根拠リンク付きの調査候補

2026-10-07。通常投稿の設定・頻度・認証・上限は変更しない。新しいWeb画面はない。
既存 `local_bot.py` に `radar` サブコマンドを追加した。
探索結果は共有SQLiteの `radar_*` テーブル、レポートは
`outputs/social_radar/latest.json`、政治関連の記事下書きは
`outputs/articles/radar-<topic-id>/` に保存する。
`short_items` やRSS候補ファイルには投入しない。外部通知・公開APIは呼ばない。

## 初期状態と実行

```powershell
python -X utf8 local_bot.py radar dry-run
python -X utf8 local_bot.py radar report
python -X utf8 local_bot.py radar run
```

`dry-run` はAPI・資料取得・DB更新をしない。`report` は保存済み候補・ジョブ・費用・評価を表示する。
`run` も専用予算未設定なら `paid_execution_disabled` で終了する。
認証は既存の `.env` / プロセス環境の `XAI_API_KEY`。値を引数に渡さない。
新規キー・環境変数は不要。通常投稿のX OAuthは読み取らない。

設定：`config/social_radar.json`。
専用の `run_budget_usd` / `daily_budget_usd` / `monthly_budget_usd` はすべて `null`。
既存の共有月次予算が残っていても、レーダー用予算の承認とは扱わない。
例えば承認された場合だけ、3項目を `3.0 / 6.0 / 10.0` に設定する。
これは料金保証・推奨支出ではなく設定例。既存総予算とxAI予算・予備費が常に優先する。
この変更だけでは定期実行を有効にしない。

定期運用の入口は `production/run_social_radar.ps1` → `radar tick`。
`paid_schedule_enabled=false` なので初期状態では有料実行されない。
Windowsタスクは追加・変更していない。承認後、独立したトリガーで20〜30分ごとに
この入口を呼べば、JSTの4時間枠ごとに1回（計6回）の探索と期限到来した再観測を処理できる。
通常投稿タスクに追記する必要はない。PCが停止していた期間の探索はまとめて追いかけない。
共有 `outputs/articles/generation.lock` を非ブロッキングで取得するため、競合時は次回に回す。
長時間sleepしない。6カテゴリを交代させ、毎巡全ジャンルを個別検索しない。

## 何が確認済みか

実装・オフライン検証済み：

- xAI Responsesの `x_search` 呼出し、構造化出力、API引用URLとモデル整理の分離。
- 0〜5候補、最大2候補を深掘り。発見、賛否を指定しない観測、文脈・反論探索を別保存。
- 原典URL・投稿IDを正規化した出来事単位の統合。人物名だけでは統合しない。
- 原典リンク不明・資料不足は保留。私的人物・人物種別不明は候補保存対象外。
- 共通台帳予約、専用の1巡・JST日次・月次上限、費用不明時の停止。
- 政治カテゴリだけ既存 `run_article` に渡し、資料取得、原文照合、独立審査、最大2修正を再利用。
- `ready_for_review` でも人間確認が必要。生成された記事は公開されない。
- 45分後の再観測ジョブ。最大2回までの設定。現在のX Searchでは比較条件を確認できないため、
  最初の再観測後に比較不能として保留し、無意味な2回目の検索を行わない。
- 採否評価、予算停止ジョブの再開、原典の取得箇所を伴う重要続報の登録。

**実API未検証**：専用予算が未設定のため、有料呼出し0回・今回の実費0米ドル。
モデルの分類精度、候補的中率、実運用の採用率は測定していない。
ネットワークを禁止したテストの成功を本番成功とは扱わない。

## API能力と制約（2026-10-07公式資料確認）

- [X Search](https://docs.x.ai/developers/tools/x-search)：Responsesで利用し、モデルは既存と同じ
  `grok-4.7`。期間指定はUTCの **日付**。実際の投稿日時が取れなければ時間帯内と断定しない。
- [モデル](https://docs.x.ai/developers/models/grok-4.7)：入力 $2 / キャッシュ $0.5 / 出力 $6（100万トークンあたり）。
- [検索料金](https://docs.x.ai/developers/pricing)：取得投稿1件 $0.005、プロフィール1件 $0.01。
  検索回数や出力候補数で課金件数は決まらない。重複取得も費用に含まれる。
- [ツール詳細](https://docs.x.ai/developers/tools/tool-usage-details)：検索の生の結果本文は通常の応答には返らない。
  したがってモデルが説明した本文、著者、日時、返信/引用関係、反応指標を、直接確認済みデータとして採用しない。
- [引用](https://docs.x.ai/developers/tools/citations)：`output_text.annotations` のURLをAPI由来として別保存。
  引用URLがあること自体は、そこに書かれた主張の真実性の証明ではない。
- [費用](https://docs.x.ai/developers/cost-tracking)：`usage.cost_in_usd_ticks / 1e10` を実測課金として保存。
  投稿/プロフィール取得数、トークン、キャッシュ、推論を別表示。推論は出力トークンに再加算しない。

`requested` は送った条件、`executed_conditions=null` は実際の内部検索条件を直接確認できない状態。
原典IDはAPI引用URLから解析可能だが、投稿の本文・著者ID・日時・引用/返信関係・エンゲージメントの
直接取得アダプターは初期版では未接続。`event_at=null` とモデル申告の `reported_event_at` を分ける。
この制約下でも出典リンク・切り口・反論の調査候補を表示できる。

`max_tool_calls=1`、出力長・入力サイズ・時間・呼出し総数を制限するが、
**取得投稿数や1リクエスト課金をAPI側で厳密に保証するものではない**。
1検索で0.75ドルの検索用余裕＋トークン見積を予約する。応答費用が予約を超えれば実費を台帳へ計上し、
以後のレーダー有料処理を停止する。タイムアウト、認証エラー、429、5xxの自動再試行は0回。
課金不明の予約は解放しない。記事用APIも同じ台帳を使用し、費用不明なら追加呼出しを遮断する。

## 指標の取り扱い

`metrics()` は直接検証済みの `measurement` レコードだけが対象。
discovery/context、別の反応対象、根拠不足は批判割合の分母に混ぜない。
判定可能な支持・批判・中立を分母とし、判定不能は別記する。
著者不明がある場合はユニーク人数をnullにする。引用であることだけでは批判にしない。
同一投稿の矛盾した分類は判定不能に落とす。少数サンプルでも確率・母集団の割合と解釈しない。

`compare()` は条件だけでなく取得完全性・上限到達・実行条件確認・投稿時刻を検査する。
新しく取得した古い反応は増加に数えない。現在の検索アダプターではすべて比較不能。
指標関数と独立軸の分類保存スキーマは将来の直接取得アダプターのために用意したが、
モデルの検索要約をそこへ流し込む裏口は設けていない。
反応確認度と事実確認状況は別フィールド。記事審査を通過しても反応規模の確認にはならない。
100点スコアは未実装・無効。初期受入には必要ない。

## 続報・評価・再開

表現変更だけでは別下書きを作らない。新しい根拠URLは `pending_update` に残す。
重要な更新は人が内容を確認してから次で登録する。元資料を安全な既存取得処理で取得し、
指定した原文との一致を検査する。続報にも既存の記事審査が必要。

```powershell
python -X utf8 local_bot.py radar confirm-update --topic <ID> --source <原典URL> --quote '原文の短い引用' --event-at '2026-10-07T09:00:00+09:00' --reason '前回から変更された点'
python -X utf8 local_bot.py radar evaluate --topic <ID> --accurate yes --adopted no --duplicate no --reason '根拠は正しいが配信先に不適合'
python -X utf8 local_bot.py radar run --job <予算停止ジョブID>
```

評価未入力は不採用に数えない。採用0件なら採用単価はnull。
共通探索費用は候補ごとに重複加算せず、全API費用÷採用数で会計上の単価を示す。
費用不明時の `accounted_usd` は予約額であり実測費用ではない。
初回発見遅延は出来事日時が直接未確認のため未算出。網羅率・再現率は測定しない。

費用不明・応答消失・中断で `ambiguous/running` のジョブは自動再送しない。
まずプロバイダー課金と台帳・保存済み出力を手動照合すること。予約・履歴の削除で再開しない。
成功した検索段階と記事段階を再利用し、既存記事 `run.json` の入力・設定を保つ。

## 保存・無効化・復旧

検索由来の原文全文・プロフィールは保持しない。モデル調査メモは既定7日で本文を期限処理し、
ID・リンク・費用・重複防止履歴を残す。既存記事の出典保存ルールは変更しない。
期限処理はCLI実行時。無効化中は実行されない。
[API向け利用規約](https://x.ai/legal/terms-of-service-enterprise)を確認したが、
将来X直接取得を追加するときは、その契約の保存・削除要件を別途確認すること。
バックアップや利用者が複製した出力まで自動消去するものではない。

無効化は `enabled=false`。専用トリガーを設けた場合はそのトリガーだけ無効化する。
通常Botは引き続き動く。コードの取り消しはこの機能のコミットだけを `git revert` する。
共有DBを古いバックアップで上書きしない（その後の投稿・費用履歴が失われる）。
追加テーブルは既存Botから参照されず、消す必要はない。
